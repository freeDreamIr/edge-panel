# Edge Panel

پنل فارسی مدیریت مسیرهای HAProxy و صفحات Nginx روی Ubuntu 24.04. HAProxy روی ۴۴۳، TLS را باز می‌کند و اتصال‌های دارای مسیر تعریف‌شده را به نود متناظر می‌فرستد. Nginx سایت و پنل مدیریت HTTPS را روی همان دامنه ارائه می‌کند. این بسته روی سرور واسط نصب می‌شود. نود Xray و پنل پاسارگارد موجود جداگانه باقی می‌مانند.

## پیش از نصب

- یک سرور Ubuntu 24.04 با SSH و دسترسی sudo در نظر بگیرید. نصب روی ماشینی که از قبل روی پورت ۴۴۳ سرویس دارد متوقف می‌شود. برای نصب اول، سرور جداگانه انتخاب کنید.
- برای مثال، رکورد IPv4 دامنهٔ `api.example.com` باید به IP عمومی سرور واسط اشاره کند. اگر سایت فارسی را روی دامنهٔ اصلی می‌خواهید، رکورد IPv4 آن را هم تنظیم کنید. دامنه‌ها باید مستقیم به این سرور برسند. اگر فقط IPv4 دارید رکورد AAAA نادرست یا قدیمی را بردارید.
- پورت‌های TCP 80 و 443 و پورت SSH را در فایروال سرور و ارائه‌دهنده مجاز کنید. پورت‌های 8081 و 15000 و 15001 محلی هستند. اگر IP شناور دارید، اول آن را طبق راهنمای میزبان به سرور اختصاص دهید و در سیستم‌عامل پیکربندی کنید.
- نصب‌کننده یک سرویس مستقل به نام `edge-haproxy` و یک فایل Nginx اضافه می‌کند. از Nginx موجود با همان نام دامنه استفاده نکنید. برای دریافت گواهی، HTTP-01 باید از بیرون در دسترس باشد.

## نصب

روی سرور واسط:

```bash
git clone https://github.com/freeDreamIr/edge-panel.git
cd edge-panel
sudo bash install.sh api.example.com YOUR_REAL_EMAIL
```

برای اضافه کردن سایت فارسی در **نصب اول**، دامنهٔ اصلی را به‌عنوان آرگومان سوم بدهید:

```bash
sudo bash install.sh api.example.com YOUR_REAL_EMAIL example.com
```

در مرورگر آدرس `https://api.example.com/edge-panel/` را باز کنید. نام کاربری `admin` است. نصب اول و اولین ارتقا از نسخهٔ ورود با رمز تنها، یک رمز تصادفی تولید می‌کنند و آن را در خروجی ترمینال نشان می‌دهند. فقط هش رمز روی سرور ذخیره می‌شود. برای تولید رمز تازه و باطل کردن نشست‌های قبلی، گزینهٔ `--rotate-admin` را به نصب‌کننده بدهید.

برای ارتقای نصب موجود، در همان پوشهٔ سورس:

```bash
git pull --ff-only
sudo bash install.sh api.example.com YOUR_REAL_EMAIL
```

دامنه و آرگومان اختیاری دامنهٔ اصلی را مطابق نصب قبلی وارد کنید. اگر پیش‌تر از `/edge-panel` یا زیرمسیر آن برای مسیریابی استفاده کرده‌اید، پیش از ارتقا آن را در نسخهٔ قبلی تغییر دهید. این پیشوند برای پنل رزرو شده است.

دسترسی محلی از طریق تونل SSH هم در `http://127.0.0.1:15001` برقرار است:

```bash
ssh -N -L 15001:127.0.0.1:15001 USER@SERVER_IP
```

- **مسیرها** برای افزودن، ویرایش و حذف مقصدهای HAProxy است. پنل قبل از بازخوانی، کانفیگ جدید را بررسی می‌کند.
- **صفحات وب** عنوان و متن صفحهٔ API و سایت پیش‌فرض را تغییر می‌دهد. تغییر صفحه به بازخوانی Nginx نیاز ندارد.
- **سرویس‌ها** وضعیت HAProxy، Nginx، سرویس پنل و تایمر Certbot را نشان می‌دهد. بررسی کانفیگ، بازخوانی سرویس‌ها و مشاهدهٔ تاریخ اعتبار گواهی هم در همین بخش‌اند.

DNS، فایروال میزبان، تنظیم اولیهٔ دامنه و اینباند پاسارگارد در سامانه‌های خودشان انجام می‌شوند. پنل دستور شل یا ویرایش فایل خام ارائه نمی‌دهد.

## اتصال به پاسارگارد

ابتدا با **یک کاربر آزمایشی** و بدون تغییر اینباند کاربران فعال تست کنید.

| محل تنظیم | مثال |
|---|---|
| پنل Edge Panel | مسیر `/s2`، مقصد `node.example.com`، پورت `8080` |
| اینباند مقصد در پاسارگارد | VLESS از نوع TCP/RAW با هدر HTTP و مسیر `/s2`، بدون TLS بیرونی |
| Host یا پروفایل آزمایشی کلاینت | Address و SNI برابر `api.example.com`، پورت 443، TLS فعال |
| نوع انتقال کلاینت | TCP/RAW، Header Type برابر HTTP، Path برابر `/s2`، ALPN برابر `http/1.1` |
| هدر HTTP Host | مطابق تنظیمات اینباند؛ برای یک اینباند آزمایشی می‌تواند همان دامنهٔ درگاه باشد |

UUID و مقدار `encryption` را از **پروفایل همان اینباند** بگیرید و اعتبارسنجی گواهی را فعال نگه دارید. مقدار `flow` برای این الگو خالی است. TLS بیرونی در واسط پایان می‌یابد و اینباند مقصد TLS جداگانه دریافت نمی‌کند. برای مقصد خارج از شبکهٔ خصوصی، رمزنگاری داخلی VLESS را در خود Xray فعال کنید و پورت مقصد را در فایروال آن به IP خروجی سرور واسط محدود کنید. لینک‌های VLESS، رمز پنل و کلید خصوصی گواهی را در مخزن قرار ندهید.

مسیر باید با خط آغازین `GET /s2 HTTP/1.1` مطابقت داشته باشد. مسیر، عامل احراز هویت نیست و احراز هویت کاربر در VLESS انجام می‌شود. از مسیرهای رزروشده‌ای که سایت عمومی نیاز دارد استفاده نکنید. WebSocket، REALITY و اینباند مقصد TLS‌دار این بسته را پوشش نمی‌دهند. برای شروع Fragment را خاموش نگه دارید تا اتصال پایه قابل مقایسه باشد. TLS، سایت عادی و اتصال موفق از یک اپراتور به‌تنهایی معیار عبور پایدار از DPI نیستند.

## بررسی روی سرور

```bash
sudo nginx -t
sudo haproxy -c -f /etc/edge-panel/haproxy.cfg
sudo systemctl status edge-haproxy edge-panel nginx
sudo journalctl -u edge-haproxy -u edge-panel -n 50
sudo certbot renew --cert-name edge-panel --dry-run
```

در مرورگر، آدرس دامنهٔ API باید صفحهٔ انگلیسی وب را با گواهی معتبر نشان دهد. این تست را جدا از تست پروفایل VLESS انجام دهید. اگر صفحه باز می‌شود ولی پروفایل نه، پورت و مسیر واقعی اینباند و سرور مقصد ثبت‌شده در پنل را بررسی کنید. اگر Nginx برای دامنهٔ API صفحهٔ متفاوتی می‌دهد، وجود فایل دیگری با همان `server_name` را بررسی کنید.

مستندات [Xray RAW](https://xtls.github.io/en/config/transports/raw.html)، [VLESS](https://xtls.github.io/en/config/inbounds/vless.html) و [HAProxy 2.8](https://docs.haproxy.org/2.8/configuration.html).
